# Podcast Final Edit

Use `python3 scripts/final_edit.py candidates --transcript ALIGNED_JSON --output NEW_JSON [--silences SILENCE_JSON]`. Alternatively use `--audio AUDIO` for FFmpeg silence detection; its SHA-256 must match the aligned transcript. Silence input is an observed list of `{start,end}` intervals in the same audio timebase. The detector proposes isolated filler tokens and recording-control phrases with context warnings. Meaning-bearing fillers, emotion and breaths remain kept. All candidates are `keep_pending_review`; no automatic deletion or release approval is produced. Review neighboring speech before constructing a sample EDL.

Use `python3 scripts/final_edit.py render-review --edl EDL_JSON --output NEW_WAV --report NEW_REPORT`. This is a thin invocation of `../podcast-production-workflow/scripts/render_sample_edl.py`, preserving its schema/source-hash checks, 48 kHz sample EDL timebase, crossfade accounting, immutable output behavior and review-only status. An external finished delivery file does not need this EDL route. The wrapper does not fabricate editorial/listening approval or replace the existing release gates.

Before pursuing automated rough cuts or evaluating quality, read [references/rough-cut-research.md](references/rough-cut-research.md). Keep the existing manual restore review workflow and retain rejected candidates for analysis.

Before deriving filler cut endpoints, also read [references/acoustic-boundaries.md](references/acoustic-boundaries.md). ASR/CTC token intervals can leave audible tails; endpoint expansion can swallow the next syllable. Check the full crossfade neighborhood and actual contextual A/B, preserve ambiguous cases, and distinguish recognition changes from verified phonetic removal.

Validation: `python3 -m unittest discover -s tests -v` checks semantic fillers are preserved and invalid intervals are rejected.

Final Edit is optional when a finished/mastered audio file is supplied. It must not delay transcription→enrichment→release→publication. Keep automatic filler/control/silence removal conservative and sample-bound; manual editor exports remain valid inputs. Future comparisons should pair manual edit decisions with AI candidate intervals and listening outcomes, preserving the source and accepted edit provenance.

## PAYG verbatim calibration

Read your Doubao PAYG ASR setup guide (the owner maintains it outside this repository) for setup, range manifests, evidence and Whisper cross-checks. When the user has authorized the configured Doubao ASR for calibration within the task audio scope (check the task record; never assume), agents may use it proactively; honor any stricter user restrictions and retain exact source/range bindings. Calibration does not require local Whisper to fail. Within that authority, use `python3 scripts/volc_asr.py --audio ANALYSIS_16K_MONO_PCM16_WAV --output-dir NEW_DIR --billing hourly [--start-sample N --end-sample N] [--speaker-info]`. The sample arguments are in the 16 kHz analysis clock, not the 48 kHz source EDL clock. The default request bound is 120 seconds; use a frozen range manifest and overlap evidence for longer recordings. Runtime dependency: `websocket-client`; audio decoding stays local. The API key is read from `VOLC_ASR_API_KEY` (override its variable name with `--key-env`), never from command-line values.

This helper preserves a checkpoint, all sanitized provider responses, the terminal result, exact source/range/PCM hashes and QC. It selects the activated hourly or concurrency resource explicitly and sends/receives concurrently. A failed attempt exits nonzero, retains evidence, and is never automatically retried or reused. Outputs are immutable directories. DDC/ITN/punctuation are disabled and two-pass recognition enabled; verbatim completeness is still unproven. Provider timestamps remain estimates. Negative-time substantive tokens, terminal quantization and chunk overlaps require review before deriving cut coordinates. Speaker IDs are local to each request; do not equate them with identities or pure channels.

`tests/test_volc_asr.py` checks binary termination, truncated/error frames, final duration/completeness, unusable timestamps and initialization failure with zero audio transmission and credential redaction. Network-free fixtures do not replace an actual provider sample.

For a frozen overlapping range plan (`source_sha256`, `source_total_frames`, `sample_rate_hz=16000`, and records with `start/end/core_start/core_end/directory`), use `python3 scripts/merge_asr.py --plan PLAN_JSON --source-total-samples ACTUAL_DECODED_48K_FRAMES --output-dir NEW_DIR`. Each directory must contain an immutable recognized ASR report, final response and raw response stream whose hashes match. Cores cover the analysis once without gaps; context overlaps are compared separately. Request-local speaker IDs remain scoped, chunk seams are protected from cutting, and raw words/corrections are retained. The observed 16k→48k resampling tail difference is explicit. Integer coordinates represent ASR estimates and require acoustic validation before edits. Character agreement in overlaps is consistency evidence, never an accuracy or verbatim-completeness claim.

## Shared route sample EDL

Use `python3 scripts/render_routes.py --edl SHARED_EDL_JSON --output-dir NEW_DIR` to apply exactly the same half-open integer sample cuts and crossfade to every decoded route. The EDL contains `sample_rate_hz=48000`, `source_total_samples`, `crossfade_samples`, sorted `cuts` with `start_sample/end_sample`, and `tracks` with unique safe `id`, `path`, `sha256`, and the absolute FFmpeg `stream_index` (default 0 for a single WAV). Do not substitute container duration for decoded samples. All routes must decode to the exact shared clock before any output is rendered; mismatched source hashes, rates or lengths fail. The helper accepts mono/stereo routes without resampling, downmixing or gain changes and requires FFmpeg, FFprobe and NumPy.

Outputs use float PCM WAV, preserving integer PCM up to 24 bits and native float32 precision. PCM32/PCM64, float64 and unknown high-precision integer sources are rejected before rendering. Lossy inputs only support comparison to their decoded samples, never recovery of original PCM. Every non-transition span is compared sample-for-sample against its mapped source after decoding the actual output. Crossfades consume `crossfade_samples` per join and have two source contributors; inverse mapping excludes them. The report binds inputs, EDL, tools, output hashes, actual counts and retained-sample proof. It always requires listening review, and never converts a hypothesis into editorial or release approval. A failed directory is retained and cannot be reused; choose a new revision. These guarantees verify synchronized mechanics, not semantic deletion quality or exact perceptual boundaries.

Use `python3 scripts/final_edit.py word-candidates --words MERGED_WORDS_JSON --output NEW_JSON` for fillers occurring **inside** full utterances. It snapshots the word evidence once for content/hash consistency and validates strict boolean verification/protection flags and integer coordinates/order/unique IDs, preserves source analysis identity, request-scoped speaker provenance, seam/zero-length protection, overlapping evidence, eight neighboring words on each side and substantive unlocated tokens. Every candidate remains `keep_pending_review` with no proposed cut interval. Affirmative “嗯”, emotional hesitation and breaths require contextual listening; lexical detection never supplies a semantic deletion label. A ledger is not an EDL, and ASR-estimated 48k coordinates remain unverified until acoustic calibration.

## Lessons from EP04 (pilot observations, not universal rules)

- A user rough cut is handled by the rough-cut recovery route in `podcast-production-workflow`, not by this skill's candidate generator.
- EP04 ASR/CTC filler intervals undershot the audible filler; a pilot suggested a 20 ms analysis window / 5 ms hop and a valley of at least 30 ms and 12 dB below the core. Use an estimated pitch period only for reliably voiced material; a fixed window is not a universal phonetic boundary guarantee. Preserve ambiguous, unvoiced, overlapping and semantic cases per [acoustic-boundaries.md](references/acoustic-boundaries.md), keep an exception list for meaningful words (e.g. “额度”), and validate a 10–20-cut pilot (cut → independent ASR recheck → listening) before adopting a method for a whole episode. A reported “42 of 46 residual” result needs its exact review artifact and denominator; ASR disappearance alone does not establish audible removal.
- Ask for the filler policy per token with source counts at intake.
